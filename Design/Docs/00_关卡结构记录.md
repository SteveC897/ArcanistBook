## 1. 门规则（图例原文 + 确认）

| 颜色 | 规则（原图） | 设计含义 |
|---|---|---|
| 🟩 绿门 | 可自由通行 | 普通通道 / 区域连接 |
| 🟦 蓝门 | 可以进；遭遇战开始后封闭；遭遇战结束后可自由通行 | 遭遇战"竞技场锁" |
| 🟥 红门 | 一开始封死；遭遇战结束后可自由通行 | 进度门（Boss 门、区域出口） |

**门的方向性（已确认）**：**所有横着的门 = 地板上的洞**——封死时有挡板、不可通行；敞开时**双向**通行，是楼层之间的开口。竖着的门就是墙上的通道门。

> 全关只需要两个概念：`DoorColor { Green, Blue, Red }` + `Encounter` 的开始/清场事件。**这是本关唯一需要写的"关卡系统"。**

## 4. 流程（已确认）

1. P0 教学区 → 绿门 → A1 存档点
2. A1 → A2：车轮战 3 轮（近战+远程+重装组合），蓝门锁场；清场后转常规配置
3. A2 → A3（地板洞）：上层较多远程兵
4. 从中部底层 B4 开始，用**垫脚平台**逐层向上：B4 → B3 → B2 → B1；两条电梯激活后可快速往返（中途不停）
5. 到右翼 C1：重装兵遭遇战（蓝门锁场，1 只）；清场后场上仍常驻 1 只重装兵、**不封门**，可以直接跳过
6. 进 C2 小房间**拾取冲刺**，返回 C1
7. 上 C1 二层，用**冲刺越过缺口**（C3），继续推进
8. 折返 → 左翼 A1 侧；A2 清场后左墙红门开启 → D1 Boss 房
9. 击败 Boss → **直接结算**（不进探索）
10. 再进游戏 → 回到**上次存档的进度**（见 §5）

> 具体「继续推进」到 Boss 的接法图里没画，待补：是回电梯折返，还是另有一条上行通道。

## 5. 重生 / 存档 / 遭遇战状态（已确认）

| 规则 | 结论 | 实现要点 |
|---|---|---|
| 非 Boss 敌人刷新 | **只有在存档点"休息 / 复生"后才刷新**；进出房间不刷新 | `Checkpoint.OnRest/OnRespawn → Spawner.Refresh()` |
| 遭遇战未通过 | 死亡或退出后再来，**仍是遭遇战** | 清场状态默认 false，直到通过 |
| 遭遇战已通过 | 之后进入为**常规配置**；坐存档点刷新后依旧是常规配置 | `ProgressState.ClearedEncounters` 持久化 |
| 遭遇战中 / 战后的配置 | 两套（车轮战波次 vs 常驻杂兵） | CSV 的 `phase=encounter / regular` + `requireClear` |
| Boss 战失败 | **Boss 直接刷新到满状态**，从头打（阶段重置） | Boss 不参与常规刷新，死亡/重生时 `Boss.ResetToPhase1()` |
| Boss 击败 | **直接结算**；再进游戏回到上次存档进度。**仅当前切片如此**；正式项目可继续探索或走回 | 结算页 → 读档 |
| 存档点是否回血 / 补满 | **待定**（你补） | 若要，`Checkpoint` 上加 heal |

**实现建议（1–2 小时）**：`ProgressState { checkpointId, clearedRoomIds, bossDefeated }`，用 `PlayerPrefs` 或小 JSON 落盘；再加一个编辑器调试菜单/快捷键"清空进度"，否则试玩时每次都要从头打。
> ⚠️ 注意：既然你要"退出游戏再进保留进度"，就必须**落盘**；如果切片不做存档，退出即从头开始——这一条会多出 1–2 小时工时，D3 的排期要算进去。

## 6. 敌人配置表 `Design/Numbers/EnemyWaves.csv`

| 字段 | 说明 | 示例 |
|---|---|---|
| `groupId` | 生成组唯一 ID（排查日志用） | `A2_W2_H` |
| `roomId` | 房间 ID（见 §2） | `A2` |
| `phase` | `encounter`=遭遇战波次；`regular`=常驻配置 | `encounter` |
| `wave` | 遭遇战波次（从 1 起）；`regular` 填 1 | `2` |
| `enemyId` | 敌人类型 ID | `E_Heavy` |
| `count` | 该生成点一次生成的数量 | `1` |
| `spawnPointId` | 场景里的生成点标记（空物体）ID | `SP_A2_W2_H` |
| `spawnDelay` | 秒；波次开始后延迟多久生成 | `1` |
| `requireClear` | 需要"该房间遭遇战已通过"才生成；空 = 无条件 | `A2` |
| `note` | 备注（**不要用英文逗号**） | `重装兵延后入场` |

**用法约定**：
- 一轮打完 → 下一波开始；`spawnDelay` 只在该波开始时算一次。
- `regular` 行在"房间加载 / 存档点刷新"时生成，且每次刷新都重新出。
- `requireClear` 有值的行，等于"清场后才存在的常驻配置"（A2、C1 的战后配置）。
- 后续接法二选一：① Editor 导入器直接读 `Design/Numbers/`（省复制，点菜单触发）；② 复制进 `Assets/_Project/Data/Source/` 自动触发导入。**先按 ①**。
- Boss 数值与招式不在本表，另配 Boss 表。

## 7. 工期与范围提醒

- 按此图首通估 **4–6 分钟**（含 Boss 6–8 分钟），比清单 A3 写的"完整 90 秒"大一档 → **A3 验收口径建议改成"一局 3–5 分钟，含 Boss；完整流程含过场 8–10 分钟"**。
- 成本分级：
  - **便宜**：三色门 + 遭遇战波次（2–4 h，且是"关卡设计"最可讲的证据）；垫脚平台（0.5 h）；冲刺能力门≈免费（缺口 + 提示 + 拾取，0.5 h）。
  - **贵**：电梯（Kinematic 玩家站在平台上要被带走，Motor 要加 carried delta，1–2 h）；进度落盘 + 存档（1–2 h）。
- **分级落地（D3 闸门）**：
  - 最小闭环：P0 → A2（车轮战）→ A1 存档 → D1 Boss，90–120 秒。
  - 标准：+ B4/B1 两层 + C1 重装兵 + 蓝门锁场，约 3 分钟。
  - 锦上添花：+ 电梯、C2 冲刺、C3 能力门、A3 远程房，约 5 分钟。
- 如果时间不够：**优先保"三色门 + 蓝门锁场 + Boss 结算/读档"**，电梯降级成静态平台，C2/C3 可以砍（冲刺直接作为初始能力）。
